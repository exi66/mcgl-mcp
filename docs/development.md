# Разработка

## Запуск из исходников

Нужны Node.js 22+ и pnpm.

```bash
pnpm install
pnpm build
cp .env.example .env   # для разработки: креды тестового аккаунта, LOG_LEVEL
```

В конфиге MCP-клиента: `"command": "node"`, `"args": ["<путь>/mcgl-mcp/dist/entry/stdio.js"]`.

| Команда            | Что делает                                              |
| ------------------ | ------------------------------------------------------- |
| `pnpm dev:stdio`   | stdio-сервер из исходников (tsx), настройки из `.env`   |
| `pnpm dev:http`    | HTTP-сервер из исходников с перезапуском при изменениях |
| `pnpm inspect`     | MCP Inspector на собранный stdio-сервер                 |
| `pnpm format`      | форматирование Prettier (CI проверяет `format:check`)   |
| `pnpm typecheck`   | проверка типов в `src`, тестах и скриптах               |
| `pnpm test`        | тесты без сети                                          |
| `pnpm check:login` | ручная проверка входа (тратит 2 попытки входа)          |

## Устройство кода

- `src/entry/` — точки входа: `stdio.ts` (npm-пакет) и `http.ts` (публичный сервер).
- `src/forum/` — работа с форумом:
  - `http.ts` — HTTP-клиент: куки, редиректы, повторы;
  - `health.ts` — circuit breaker;
  - `player-session.ts` — вход и перелогин;
  - `reader.ts` — чтение и пагинация тем;
  - `parsers/` — HTML → данные.
- `src/mcp/` — MCP: сборка сервера и инструменты.

Подробности о форуме и о том, почему код устроен так, а не иначе, — в [forum.md](forum.md).

### Новый инструмент

1. Метод чтения — в `ForumReader` или рядом, парсер страницы — в `src/forum/parsers/`.
2. Объявление: `definePublicTool(...)` или `definePlayerTool(...)` в `src/mcp/tools/`, затем добавить его в массив в `src/mcp/tools/index.ts`.
3. Описание и параметры пишутся на английском (экономия токенов), ответ отдаётся через `jsonResult`.
4. Ошибки, которые должен увидеть агент, бросаются как `ForumError` или его наследники.

Player-инструменты регистрируются только при наличии сессии игрока и в HTTP-режим не попадают. Обращения к форуму внутри них оборачиваются в `ctx.session.withAuth(...)`, страницы получаются через `ctx.session.getAuthed(...)`.

Прежде чем писать парсер, посмотрите живую разметку страницы (curl) и сохраните её как фикстуру.

## Тесты

```bash
pnpm test              # все тесты без сети (их же гоняет CI)
pnpm test:watch
pnpm test:live         # smoke-тесты на настоящем форуме; креды из .env необязательны
pnpm fixtures:update   # перекачать страницы форума в test/fixtures
```

| Папка           | Что проверяется                                                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `test/parsers/` | конвертер bbCode → текст на HTML-фрагментах; парсеры страниц на фикстурах                                                        |
| `test/forum/`   | куки, редиректы, повторы, circuit breaker; вход, перелогин, блокировка после неверного пароля; пагинация тем; названия предметов |
| `test/mcp/`     | MCP целиком: клиент SDK ↔ сервер (`InMemoryTransport`) ↔ фейковый форум                                                          |
| `test/live/`    | только `pnpm test:live`: живая разметка всё ещё разбирается                                                                      |

- **Фейковый форум.** Сеть тестируется против локального http-сервера, который поднимается в тесте (`test/helpers/fake-forum.ts`), поэтому проверяется настоящий `ForumHttp`, без моков `fetch`.
- **Логин.** `login-forum.ts` воспроизводит настоящий поток входа.
- **Синтетические темы.** `topic-html.ts` генерирует темы любого размера для тестов пагинации.
- **Фикстуры** — замороженные копии страниц форума, они лежат в git. Если форум поменял вёрстку, запустите `pnpm fixtures:update` и посмотрите, какие тесты упали.

`tsconfig.json` проверяет типы в `src`, тестах и скриптах; `tsconfig.build.json` собирает только `src` в `dist`.

## CI и релизы

- **CI** ([ci.yml](../.github/workflows/ci.yml)) на push в `main` и на PR прогоняет проверку формата, typecheck, тесты, сборку и `npm pack --dry-run`.
- **Релиз** ([publish.yml](../.github/workflows/publish.yml)) запускается тегом:

  ```bash
  git tag v0.2.0
  git push origin v0.2.0
  ```

  - **Версия берётся из тега.** В `package.json` лежит заглушка `0.0.0-dev`, менять её руками не нужно.
  - **Пререлизы** (`v1.0.0-beta.1`) публикуются с dist-tag `next`, поэтому `npx mcgl-mcp` по-прежнему ставит последнюю стабильную версию.
  - **Перед публикацией** `prepublishOnly` прогоняет typecheck, тесты и сборку.
  - **Без токена.** Публикация идёт через trusted publishing (OIDC). На npmjs.com в настройках пакета заведён Trusted Publisher: GitHub Actions, `exi66/mcgl-mcp`, `publish.yml`, разрешён `npm publish`. npm сам проверяет, что публикует этот workflow, и добавляет provenance. Секретов в репозитории нет.
  - **Если переименовать `publish.yml`** или перенести репозиторий, Trusted Publisher на npmjs.com нужно пересоздать.
  - **Не добавлять `registry-url` в `actions/setup-node`.** С ним setup-node подставляет в `.npmrc` токен-заглушку, npm отправляет её вместо OIDC и получает 404 на публикацию.
- **Защита репозитория** (Settings → Rules → Rulesets):
  - **«Protect main».** Нельзя force push и удаление ветки. Изменения идут через PR с зелёным CI (`check`) и одобрением. PR, который трогает файлы из [CODEOWNERS](../.github/CODEOWNERS) (workflow, `package.json`, lock-файл), требует одобрения владельца.
  - **«Protect release tags».** Создавать, двигать и удалять теги `v*` (то есть публиковать) может только владелец.
  - **Bypass.** Владелец репозитория (роль Admin) обходит оба правила и может пушить в `main` напрямую.

Что попадёт в пакет: `npm pack --dry-run`. Идут только `dist/**/*.js` (без `dist/dev`), README и LICENSE.

## Свой HTTP-сервер

Публичный режим: Streamable HTTP, stateless, только инструменты, не требующие входа. `FORUM_LOGIN` и `FORUM_PASSWORD` в этом режиме не читаются.

```bash
cp .env.example .env   # HOST, PORT, ALLOWED_HOSTS
docker compose up -d --build
```

- **Эндпоинт:** `POST /public/mcp`, TLS — на reverse-proxy (Caddy, nginx).
- **`/health`** — состояние сервера и форума (по данным circuit breaker).
- **`ALLOWED_HOSTS`** — список доменов через запятую для защиты от DNS rebinding.

Перед открытием наружу нужны лимиты на входящие запросы: сейчас все клиенты делят одну очередь запросов к форуму.
