# Как сервер работает с форумом

API у форума нет. Сервер ходит на него как браузер: получает HTML, отправляет формы, держит куку `PHPSESSID` и разбирает страницы парсерами из `src/forum/parsers/`.

Списки тем и страницы тем свёрстаны одинаково во всём форуме, включая сообщества (`/htopic/N`, `/hpost/N`), поэтому парсеры общие.

## Вход

1. `GET /guilogin/`: из формы `form[action="/login.php"]` берутся скрытые поля `form`, `ref`, `fcode`, `recap`.
2. `POST /login.php` с этими полями плюс `login` и `pass`.
   - **Успех:** 302 на `/main/`, в шапке появляется ник (`a.button[href="/profilemain/"] .text`).
   - **Неудача:** 302 на `/guilogin/4?f=N`, текст ошибки в `table.alert td.caption` («Введенный логин или пароль неверны! Попыток входа осталось: N…»).

Особенности:

- **`fcode` обязателен.** Без него вход отклоняется и тратится попытка.
- **reCAPTCHA v3 сервер форума не проверяет**, поэтому `recap` уходит пустым.
- **У входов есть лимит попыток, похоже — на IP.** После неудачного логина `PlayerSession` больше не пробует войти, пока процесс не перезапустят.
- **Гость определяется по кнопке «Войти» в шапке** (`a.button[href="/guilogin/"]`). Форма ответа в теме видна и гостю, поэтому по ней о логине судить нельзя.
- **Протухшая сессия переустанавливается сама.** Если страница пришла гостевой, бросается `SessionExpiredError`, сессия перелогинивается и повторяет операцию один раз.

Ручная проверка без MCP (креды из `.env`): `pnpm check:login`. Каждый запуск тратит 2 входа.

## Пагинация тем

В URL форума страницы нумеруются с 0 (`/topic/ID/0`), в инструментах — с 1. Номер страницы за пределами темы форум не исправляет, а отдаёт пустую страницу.

Сколько постов на странице, форум решает по настройкам игрока: у гостя и игроков бывает от 15 до 100. Агенту сто постов за раз дорого, поэтому `forum_get_topic` отдаёт свои страницы фиксированного размера (15, параметр `pageSize`) поверх пагинации форума (`ForumReader` в `src/forum/reader.ts`):

- **Нумерация.** Номера постов `#N` в теме сквозные, удалённые посты тоже нумеруются. Поэтому страница `v` — это посты `#(v-1)*15+1 … #v*15`, и нужная страница форума вычисляется из номера.
- **По умолчанию — последние посты.** Без `page` инструмент отдаёт последние 15 постов: в больших темах обычно нужен конец. Если на последней странице форума их меньше, недостающие берутся с предыдущей.
- **Число страниц из списков тем.** В списках тем у каждой темы указано, сколько у неё страниц. `ForumReader` запоминает это число на 10 минут и потом открывает последнюю страницу темы одним запросом. Если тема за это время выросла на новую страницу, это видно по пагинации, и reader идёт обычным путём через первую страницу.
- **Размер страницы форума** определяется по первой или последней странице темы и перепроверяется по номерам. Если игрок поменял настройку, reader сбрасывает кеш и пересчитывает.
- **Кеш.** Разобранные страницы форума хранятся 60 секунд, чтобы листание темы не скачивало их заново.
- **Шапка темы.** Опрос (`form[action$="/answer"]`), «Этот топик был перемещен из раздела …» и «кто читает» есть на каждой странице форума. Инструмент отдаёт их в режиме «последние» и на первой странице.

## Списки тем

- **Закрытая тема:** в списке у неё зачёркнутый заголовок (`.main-title-close`).
- **«Кто может отвечать»** (`all` / `vip` / `premium_platinum` / `moderators`) задаётся при создании темы и видно только в списках тем, на странице самой темы его нет.
- **Закреплённые темы** помечены классом `t-1`.

## Текст постов

HTML поста переводится в компактный текст (`src/forum/parsers/content.ts`). Это отрендеренный [bbCode](https://forum.minecraft-galaxy.ru/wiki/201):

- `[quote: ник] … [/quote]`, `[spoiler: заголовок] … [/spoiler]` (так же оформляется `[scroll]`);
- `[image: url]`, `[video: url]`, `[audio: url]`;
- предметы — `[Золотой блок #41]`, с метадатой — `[Красная шерсть #35:14]`;
- окна крафта, печи и наковальни — блок `[craft]`: сетка id предметов (`-` — пустой слот, `->` — результат, `x4` — количество) и легенда `124 = Ажурный камень`;
- таблицы — ячейками через `|`, списки — с `- `;
- ссылки — как `текст (url)`, редиректы форума раскрываются, ники остаются просто ником.

Удалённый пост отдаётся как `{deleted: true, number, id}`. Автор `player$0` (профиль 0) — это удалённый или заблокированный аккаунт, у него стоит `accountDeleted: true`.

## Предметы и подсказки

Всплывающие подсказки форума отдаёт эндпоинт `/object/{id}/{type}`:

- тип 1 — игрок;
- тип 2 — предмет, `?d=` — метадата;
- тип 3 — сообщество.

Ответ — JS-объект в одинарных кавычках (форум делает ему `eval`); пустой ответ означает, что объекта нет. Сервер разбирает его регуляркой (`src/forum/objects.ts`).

Названия предметов кешируются на всё время жизни процесса: предметы не меняются. За один вызов инструмента делается не больше 25 новых запросов, остальные предметы остаются как `[item #id]` и подтянутся при следующих вызовах.

## Недоступность форума

Форум самописный и время от времени лежит (`src/forum/http.ts`, `src/forum/health.ts`):

- **Повторы GET.** До 3 попыток при сетевой ошибке, таймауте или 5xx, с паузами 1 и 2 секунды.
- **POST не повторяется:** при обрыве неизвестно, дошёл ли запрос, а повтор отправки поста создал бы дубль.
- **Circuit breaker.** После 2 подряд неудачных запросов (уже с повторами) форум считается лежащим. 30 секунд запросы на него не идут, и инструменты сразу отвечают «The forum is not responding right now. Try again in Ns». Потом проходит один пробный запрос. Ответы 4xx и непонятная разметка неудачей не считаются: форум при этом жив.
- **Общий лимитер.** Между запросами к форуму выдерживается минимальная пауза (`FORUM_MIN_INTERVAL_MS`), одна на весь процесс.

## Экономия токенов

Ответы инструментов читает модель, поэтому:

- описания инструментов и служебные маркеры в тексте написаны на английском и в ASCII, а контент форума остаётся как есть, на русском;
- ответы — компактный JSON без отступов;
- флаги `false` не отдаются (`pinned`, `closed`, `deleted`, `accountDeleted` есть только при `true`); это сказано в описаниях инструментов;
- в `instructions` сервера одной фразой сказано, что форум русскоязычный и публиковать на нём нужно по-русски.

## Игроки

Всё доступно без входа:

- `/object/0/9?q=<ник>` — точный поиск без учёта регистра: `[{'id':'714893','login':'pozziittiivo'}]`. Если ника нет, форум отвечает `player$0` с id 0.
- `/object/0/4?q=<начало ника>` — автодополнение: строки `ник|группа|id`, до ~100 штук. Попадаются пустые строки и удалённые аккаунты `player$N`, они отбрасываются.
- `/forum/-<id+1>/<страница>` — темы, созданные игроком. В URL id игрока **плюс один** со знаком минус: игрок 714893 → `/forum/-714894`, а `/forum/-714893` — темы другого игрока. Разметка как у списка тем раздела, заголовок «Темы пользователя <ник>».

`forum_user_topics` по нику сначала находит id через точный поиск. Если ника нет, ошибка подсказывает ники с тем же началом, а при опечатке в середине — по первым четырём буквам.

Группа игрока (`group`, CSS-класс ника) — это привилегия: покупная (vip, premium, platinum…) или системная (модераторы, администрация). `girls` — просто цвет ника, его может выбрать любой, к полу отношения не имеет.

## Устройство форума

- `/main/` — главная со списком разделов.
- `/forum/0` — последние темы всех разделов, `/forum/1` … `/forum/11` — разделы (9 нет).
- `/topic/N`, `/post/N` — тема и отдельный пост.
- `/hforum/N` — сообщество (пользовательский сабфорум), `/htopic/N` — его раздел, `/hpost/N` — тема (гостю закрыта). На главной показаны самые популярные разделы сообществ.
- Поиск на форуме фактически не работает.
