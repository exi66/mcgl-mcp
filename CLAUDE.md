# mcgl-mcp

MCP-сервер для форума игры Minecraft Galaxy (https://forum.minecraft-galaxy.ru). API у форума нет: сервер ходит как браузер (HTML, формы, кука `PHPSESSID`) и парсит страницы cheerio.

Документация для людей:

- `README.md` — для игроков: установка, инструменты, настройки. Он же показывается на npm, поэтому держать коротким.
- `docs/forum.md` — как сервер работает с форумом.
- `docs/development.md` — разработка, тесты, релизы, хостинг.

Новые подробности устройства — туда, не в README.

## Команды

```bash
pnpm format           # prettier --write . (CI проверяет format:check)
pnpm typecheck        # tsc по src, test, scripts (tsconfig.json, noEmit)
pnpm test             # vitest, без сети
pnpm test:live        # smoke на настоящем форуме (креды из .env необязательны)
pnpm build            # чистый dist из src (tsconfig.build.json)
pnpm check:login      # ручная проверка логина (тратит 2 входа)
pnpm fixtures:update  # перекачать test/fixtures с форума
pnpm inspect          # MCP Inspector на собранный stdio-сервер
```

Перед тем как сказать «готово»: `pnpm format && pnpm typecheck && pnpm test`.

## Устройство

- `src/entry/stdio.ts` — локальный режим (npm-пакет, `npx mcgl-mcp`). С `FORUM_LOGIN`/`FORUM_PASSWORD` есть сессия игрока.
- `src/entry/http.ts` — публичный Streamable HTTP, stateless, только публичные инструменты, креды не читает.
- `src/forum/http.ts` — fetch + CookieJar + ручные редиректы + повторы GET; `health.ts` — circuit breaker; `rate-limiter.ts` — общий интервал между запросами.
- `src/forum/player-session.ts` — логин, `withAuth` (перелогин при `SessionExpiredError`), `getAuthed`.
- `src/forum/reader.ts` — чтение: пагинация тем по 15 постов поверх пагинации форума, кеши.
- `src/forum/parsers/` — HTML → данные; общие для всего форума, включая сообщества (`htopic`/`hpost`).
- `src/forum/objects.ts` — `/object/{id}/{type}` (подсказки форума), названия предметов.
- `src/mcp/tools/` — инструменты: `definePublicTool` / `definePlayerTool`, реестр в `tools/index.ts`.

## Особенности форума (проверено, не переоткрывать)

- Страницы в URL с 0 (`/topic/ID/0`), в инструментах — с 1. Номер страницы за пределами темы даёт пустую страницу, а не последнюю.
- Логин: GET `/guilogin/` → POST `/login.php` с `login`, `pass` и скрытыми `form`, `ref`, `fcode`, `recap`. Без `fcode` вход отклоняется и тратит попытку. reCAPTCHA (`recap`) сервер не проверяет. Неудача → 302 на `/guilogin/4?f=N`, текст в `table.alert td.caption`.
- Лимит попыток входа, похоже, на IP. После неудачного логина `PlayerSession` больше не пробует до перезапуска. Не перебирать пароли.
- Гость определяется по `a.button[href="/guilogin/"]` в шапке. Форма ответа видна и гостю — по ней о логине не судить.
- Ответ в тему: POST на URL темы с `form`, `addpost`, `text` (как jQuery `$.post`). Ошибка — текст со словом «Введите».
- Посты на странице форума: 15…100, по настройкам игрока. Номера `#N` сквозные, удалённые посты тоже нумеруются.
- Шапка темы (опрос `form[action$="/answer"]`, «перемещено из…», «кто читает») есть на каждой странице форума.
- Закрытая тема: заголовок с `.main-title-close` (line-through). «Кто может отвечать» видно только в списках тем.
- Автор `player$0` (профиль 0) — удалённый или заблокированный аккаунт.
- Игроки (без логина): `/object/0/9?q=ник` — точный поиск (нет → `player$0`), `/object/0/4?q=начало` — `ник|группа|id` построчно, `/forum/-<id+1>` — темы игрока (именно id+1).
- `group` у ника — привилегия (покупная или системная), `girls` — только цвет ника, не пол.
- `/object/{id}/2?d={meta}` — предмет, `/1` — игрок, `/3` — сообщество. Ответ — JS-литерал в одинарных кавычках, пусто = нет объекта.
- `/hforum/N` — сообщество (пользовательский сабфорум), `/htopic/N` — его раздел, `/hpost/N` — тема (гостю закрыта).
- Поиск на форуме не работает — не делать.

## Соглашения

- Экономия токенов агента: описания инструментов и служебные маркеры (`[quote: …]`, `[spoiler: …]`, `[image: …]`, `[craft]`, `[Item #id]`) — на английском и в ASCII. Ответы — компактный JSON, флаги `false` опускаются (`jsonResult`). Контент форума не переводится.
- Комментарии в коде — на русском.
- `ForumError` и наследники — текст для агента (`isError`); остальные исключения маскируются.
- GET повторяется (3 попытки), POST — никогда (дубль поста).
- Логи только в stderr (stdout в stdio занят протоколом). Не логировать пароли, куки, заголовки целиком.
- Новая страница форума или селектор — сначала посмотреть живую разметку (curl), затем фикстура и тест.

## Тесты

- `test/helpers/fake-forum.ts` — локальный http-сервер вместо форума; проверяется настоящий `ForumHttp`, без моков fetch.
- `test/helpers/login-forum.ts` — фейк с настоящим потоком логина; `topic-html.ts` — синтетические темы для пагинации.
- `test/fixtures/` — замороженные страницы форума (в git). Тесты парсеров на них ещё предстоят: контент будет из своего сообщества, чтобы не менялся.

## Осторожно

- Ничего не публиковать на настоящем форуме (посты, голосования) без явного подтверждения пользователя.
- `.env` содержит креды тестового аккаунта и в git не попадает.
- `main` и теги `v*` защищены rulesets; владелец в bypass, поэтому прямой пуш работает. Force push в `main` и перестановку тегов не делать без явной просьбы.
- Релиз: тег `vX.Y.Z` → `.github/workflows/publish.yml` (версия из тега, в `package.json` заглушка `0.0.0-dev`). CI: `.github/workflows/ci.yml` на push в `main` и PR.
