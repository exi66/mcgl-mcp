# mcgl-mcp

MCP-сервер для форума [Minecraft Galaxy](https://forum.minecraft-galaxy.ru/main/). API у форума нет, поэтому сервер ходит на него как браузер: HTML, формы, кука `PHPSESSID`.

**Текущее состояние:** авторизация игрока и чтение общего форума. Действий от лица игрока пока нет.

## Инструменты

Все инструменты публичные: авторизация не нужна, работают в обоих режимах. В локальном режиме с кредами страницы читаются залогиненным.

| Инструмент | Страница | Что возвращает |
|---|---|---|
| `forum_list_sections` | `/main/` | разделы 1..11 по категориям: описание, число тем и ответов, последнее сообщение |
| `forum_latest_topics` | `/forum/0/{page}` | последние темы всех разделов, у каждой указан раздел |
| `forum_list_topics` | `/forum/{id}/{page}` | темы раздела: закреплена, закрыта (зачёркнута), кто может отвечать (`all`/`vip`/`premium_platinum`/`moderators`), автор, ответы, число страниц, последнее сообщение |
| `forum_get_topic` | `/topic/{id}/{page}` | без `page` — последние 15 постов темы; с `page` — страницы по 15 от начала (`pageSize` 1..50). Всего постов и страниц; в режиме «последние» и на 1-й странице ещё опрос, системные сообщения («перемещено из…») и кто читает сейчас |
| `forum_get_post` | `/post/{id}` | один пост с номером в теме, его тема и страница `forum_get_topic`, на которой он находится |

В инструментах страницы нумеруются с 1, в URL форума — с 0.

**Пагинация тем.** Форум показывает на странице столько постов, сколько задано в настройках игрока (у гостя и игроков бывает 15…100). Агенту сто постов за раз дорого, поэтому `forum_get_topic` отдаёт свои страницы фиксированного размера поверх пагинации форума. Номера постов `#N` в теме сквозные, удалённые тоже нумеруются, так что страница `v` — это посты `#(v-1)*15+1 … #v*15`. Без `page` отдаются последние 15 постов: в больших темах обычно нужен конец. Если тема недавно встречалась в списке тем, там уже было число её страниц, и `ForumReader` открывает последнюю страницу форума одним запросом. Если тема с тех пор выросла на новую страницу, это видно по пагинации, и reader идёт обычным путём. Размер страницы форума `ForumReader` узнаёт по первой (или последней) странице темы и перепроверяет по номерам: если игрок поменял настройку, пересчитывает. Разобранные страницы форума кешируются на 60 секунд, чтобы листание темы не скачивало их заново.

**Недоступность форума.** GET повторяется до 3 раз при сетевой ошибке, таймауте или 5xx, с паузами 1 и 2 секунды. POST не повторяется: повтор может создать дубль поста. После 2 подряд неудачных запросов срабатывает circuit breaker (`src/forum/health.ts`): 30 секунд запросы на форум не идут, инструменты сразу отвечают «форум не отвечает, повтори через N секунд». Затем проходит один пробный запрос. Состояние видно в `/health` HTTP-режима.

Пост содержит номер, id, автора (ник, id, группа, статус, клан со званием, число ответов), дату, текст и рейтинг. Удалённый пост возвращается как `{deleted: true, number, id}`. Если аккаунт автора удалён или заблокирован (на форуме это `player$0`), у автора стоит `accountDeleted: true`.

Текст поста получается из отрендеренного bbCode ([справка](https://forum.minecraft-galaxy.ru/wiki/201)):

- `[quote: ник] … [/quote]`, `[spoiler: заголовок] … [/spoiler]`;
- `[image: url]`, `[video: url]`, `[audio: url]`;
- предметы — `[Золотой блок #41]`, с метадатой — `[Красная шерсть #35:14]`;
- окна крафта, печи и наковальни — `[craft]`: сетка id предметов (`-` — пустой слот, `->` — результат, `x4` — количество) и легенда `124 = Ажурный камень`;
- таблицы — ячейками через `|`, списки — с `- `;
- ссылки — как `текст (url)`, редиректы форума раскрываются.

Названия предметов берутся из эндпоинта подсказок форума `/object/{id}/2?d={meta}` (`src/forum/objects.ts`). Кеш живёт весь процесс. За один вызов инструмента делается не больше 25 новых запросов, остальные предметы остаются как `[item #id]`. Тот же эндпоинт отдаёт карточку игрока (тип 1) и сообщества (тип 3).

### Экономия токенов

- Описания инструментов и служебные маркеры в тексте — на английском и в ASCII. Контент форума остаётся как есть, на русском.
- Ответы — компактный JSON без отступов.
- Флаги `false` не отдаются (`pinned`, `closed`, `deleted`, `accountDeleted` есть только при `true`); об этом сказано в описаниях инструментов.

Парсеры в `src/forum/parsers/` общие: списки тем и страницы тем одинаково свёрстаны во всём форуме, включая сообщества (`/htopic/N`, `/hpost/N`).

## Авторизация на форуме

1. `GET /guilogin/`: из формы `form[action="/login.php"]` берутся скрытые поля `form`, `ref`, `fcode`, `recap`.
2. `POST /login.php` с этими полями плюс `login` и `pass`.
   - Успех: 302 на `/main/`, в шапке появляется ник (`a.button[href="/profilemain/"] .text`).
   - Неудача: 302 на `/guilogin/4?f=N` с плашкой `table.alert td.caption` («Введенный логин или пароль неверны! Попыток входа осталось: N…»).
3. Гостевая страница определяется по кнопке «Войти» в шапке (`a.button[href="/guilogin/"]`). Форма ответа в теме видна и гостю, поэтому по ней судить о логине нельзя.

Особенности форума:

- **`fcode` обязателен.** Без него вход отклоняется и списывается попытка.
- **reCAPTCHA v3 сервер не проверяет**, `recap` уходит пустым.
- **У входов есть лимит попыток.** Поэтому после неудачного логина `PlayerSession` больше не пробует войти, пока процесс не перезапустят.
- **Протухшая сессия переустанавливается сама.** Если страница пришла гостевой, бросается `SessionExpiredError`, сессия перелогинивается и повторяет операцию один раз.

Проверка без MCP (креды из `.env`): `pnpm check:login`. Скрипт логинится, повторно использует сессию и имитирует её протухание. Каждый запуск тратит 2 входа.

## Локальный режим

Нужен Node.js 22+. Ставить отдельно ничего не надо: клиент сам запустит пакет через `npx`.

**Claude Code:**

```bash
claude mcp add mcgl -e FORUM_LOGIN=ник -e FORUM_PASSWORD=пароль -- npx -y mcgl-mcp
```

**Claude Desktop, Cursor и другие** (`claude_desktop_config.json`, `.cursor/mcp.json` и т.п.):

```json
{
  "mcpServers": {
    "mcgl": {
      "command": "npx",
      "args": ["-y", "mcgl-mcp"],
      "env": {
        "FORUM_LOGIN": "ник",
        "FORUM_PASSWORD": "пароль"
      }
    }
  }
}
```

`FORUM_LOGIN` и `FORUM_PASSWORD` необязательны: без них доступно только чтение.

Если на Windows клиент не находит `npx`, укажи `"command": "cmd"` и `"args": ["/c", "npx", "-y", "mcgl-mcp"]`.

С кредами сервер логинится сразу при старте. Результат («Authorized as …» или текст ошибки форума) виден в логах MCP-клиента.

### Запуск из исходников

```bash
pnpm install
pnpm build
```

В конфиге клиента: `"command": "node"`, `"args": ["<путь>/mcgl-mcp/dist/entry/stdio.js"]`.

## Публикация в npm

Публикует GitHub Actions ([.github/workflows/publish.yml](.github/workflows/publish.yml)) по тегу:

```bash
git tag v0.1.0
git push origin v0.1.0
```

- **Версия берётся из тега.** В `package.json` в репозитории лежит заглушка `0.0.0-dev`, менять её руками не нужно.
- **Пререлизы** (`v1.0.0-beta.1`) публикуются с dist-tag `next`, поэтому `npx mcgl-mcp` продолжает ставить последнюю стабильную версию.
- **Тег, который не является semver,** останавливает workflow с ошибкой.
- **Пакет подписывается `--provenance`:** npm показывает, что он собран этим workflow из этого репозитория.

Один раз нужно добавить секрет `NPM_TOKEN` в Settings → Secrets and variables → Actions. Токен создаётся на npmjs.com в разделе Access Tokens → Generate New Token → Granular, с правом публикации.

Что попадёт в пакет: `npm pack --dry-run`. Идут только `dist/**/*.js` (без `dist/dev`), README и LICENSE.

## Устройство

```
src/
  entry/stdio.ts         локальный режим
  entry/http.ts          публичный режим
  dev/check-login.ts     ручная проверка авторизации
  env.ts                 конфиг из переменных окружения
  forum/
    site.ts              URL форума
    http.ts              fetch + куки + ручные редиректы + повторы GET
    health.ts            circuit breaker: форум лежит → не ходим 30 с
    cookie-jar.ts
    rate-limiter.ts      минимальный интервал между запросами (общий на процесс)
    player-session.ts    логин, проверка сессии, перелогин
    reader.ts            чтение форума (гостем или через сессию игрока)
    types.ts             формы данных, которые отдают инструменты
    parsers/
      common.ts          общие хелперы, признаки гостя, пользователи, пагинация
      topic-list.ts      главная, /forum/0, /forum/N (и разделы сообществ)
      topic.ts           тема и отдельный пост: посты, опрос, шапка
      content.ts         HTML поста (bbCode) → текст
      player.ts          форма логина
  mcp/
    define-tool.ts       definePublicTool / definePlayerTool
    tools/index.ts       реестр инструментов
    tools/public/read.ts инструменты чтения
    server.ts            сборка McpServer
```

Добавление инструмента: объявить через `definePublicTool` или `definePlayerTool` и положить в массив в `mcp/tools/index.ts`. В player-инструментах обращения к форуму оборачиваются в `ctx.session.withAuth(...)`, а страницы получаются через `ctx.session.getAuthed(...)`.

## Тесты

```bash
pnpm test              # все тесты, без сети (их же гоняет CI)
pnpm test:watch
pnpm test:live         # smoke-тесты на настоящем форуме, креды игрока из .env необязательны
pnpm fixtures:update   # перекачать страницы форума в test/fixtures
```

| Папка | Что проверяется |
|---|---|
| `test/parsers/` | конвертер bbCode → текст на коротких HTML-фрагментах; парсеры страниц на фикстурах |
| `test/forum/` | куки, редиректы, cp1251, лимитер; логин, перелогин, блокировка после неверного пароля; названия предметов (кеш, лимит запросов) |
| `test/mcp/` | MCP целиком: клиент SDK ↔ сервер (`InMemoryTransport`) ↔ фейковый форум |
| `test/live/` | только `pnpm test:live`: живая разметка всё ещё парсится |

Тесты сети работают против фейкового форума: это локальный http-сервер внутри теста (`test/helpers/fake-forum.ts`). Он отдаёт страницы из `test/fixtures/`, поэтому проверяется настоящий `ForumHttp`, без моков `fetch`.

Фикстуры — замороженные копии страниц форума, они лежат в git. Если форум поменял вёрстку, запусти `pnpm fixtures:update` и посмотри, какие тесты упали.

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) на push в `main` и на PR прогоняет typecheck, тесты, сборку и проверку состава пакета. Перед публикацией `prepublishOnly` прогоняет то же самое.

`tsconfig.json` проверяет типы в `src`, тестах и скриптах, а `tsconfig.build.json` собирает только `src` в `dist`.
